## 五、过程中的发现与 review 修复（都已修）

### 5.1 实现阶段的两个发现

1. **`releasePlayer()` 清不掉残留帧**。第一次设备实测发现终态画面仍停在 CCTV-1 的最后一帧（左上角台标可见），
   即 I2 报告里「凤凰卫视静默冻帧」的同一个现象。`releasePlayer()` 只是 `setDisplay(null)` + `release()`，
   Surface 里排队的旧解码缓冲会重新顶上来；补 `DirectVideoView.clearLastFrame()`（画两层不透明黑帧）后才真正变黑。
   **这说明 A6 必须放在终态入口的最后一步，而不是靠 release 顺带完成。**
2. **assets 不是 Gradle 眼中的测试输入**。改坏 `builtin_channels.txt` 后 `testArm64DebugUnitTest` 仍显示 `UP-TO-DATE`，
   负向验证一度假绿。已在 `app/build.gradle` 注册 `tasks.withType(Test) { inputs.file(builtin_channels.txt) }` 修复。

### 5.2 review 阶段新发现（3 项，改动后已重新构建 + 设备复测）

3. **失败决策链可能在播放线程执行**。`onError` 回调来自 IJK 事件线程；原代码在该分支只调用「内部已 post 到 UI」的三个方法，
   而 `handleChannelFailure` 会换台、操作 View、弹 Toast。已把决策与动作整体收敛到 `runOnUiThread`
   （在 UI 线程时立即执行，不改变同步语义）。
4. **主动换台没有重置连跳计数**。终态（计数 2）后用户手动切到另一个坏台，会因计数未复位而直接进终态，
   表现为「同样是坏台，有时跳、有时不跳」。已把 `switchChannel` 拆为「主动换台（清零）」与 `switchChannelInternal`（不动计数），
   自动跳台链路走后者。**设备复测**：终态后手动切回坏台，日志重新出现 `skip=1/2`（修复前不会出现）。
5. **终态重入**。多线路失败会多次到达终态入口，重复的 `clearLastFrame()` 会重复 `lockCanvas`，可能让画面闪。
   已加「同频道已处于终态则只更新失败原因」的幂等保护。

> 澄清一条观察：设备复测时 `Playback terminal` 日志出现两次（间隔约 11 s），排查后确认**不是缺陷**——
> `Input mode changed to remote` 触发了一次新的播放尝试（`Auto source switch ... attempt=2/3`），
> 第二次终态对应的是这次新尝试的失败。每次终态都对应一次独立的播放尝试，符合设计。

review 修复后重新构建并复测：连跳/终态/复位行为与修复前一致（`skip=1/2` → `skip=2/2` → terminal，3.0 s 内完成），
`regression.ps1` 仍 28/28，CCTV-1 1920x1080。

## 八、回顾

- 做得好的：
  - **先建网、再改行为**：B1 先跑通空用例确认工具链，A 组改完立刻有回归兜底
  - **负向验证暴露了真问题**：不是「补个用例」走过场，而是发现了「assets 不在测试输入里」这个会让网失效的缺陷
  - **设备侧实测抓到了 releasePlayer 清不掉帧**：如果只做静态检查，这个缺口会被当成已完成
  - 三个失败路径（onError / 线路耗尽 / 恢复链跳台）收敛到 `handleChannelFailure` 一个出口，避免了三处各写一套终态
- 遇到的问题：
  - 本机 `GRADLE_USER_HOME/gradle.properties` 固定 `org.gradle.java.home=JDK21`，Gradle 4.4 直接报 `Could not determine Java version`；用 `.codex-tmp/gradle-home-jdk8`（junction 复用 `caches`/`wrapper`）绕开，未改动全局配置
  - `~/.android/debug.keystore` 是 PKCS12 格式，AGP 3.1.4 读不了（`Invalid keystore format`）；改用 `-Pandroid.injected.signing.*` 注入 `.debug-signing/debug.jks`（alias `androiddebugkey`）
  - 脚本归位时把 `$PSScriptRoot\..` 误写成 `..\..`，被 `regression.ps1` 的 S 层当场暴露（28/28 变成 27/28），已修
  - 计划里的决策 5（用 `sourceSets` 指向 `tests/java`）实际改为标准位置 `app/src/test/java`，已同步修正计划文档
- 下轮改进：
  - B6：`check-sources.ps1` 在 `deadChannels > 0` 时以非零退出码结束，并写进发布清单
  - 拆分 `MainActivity`（顺延为 I5）入口条件已满足：回归网 + 终态已验证；建议先抽「播放状态持有对象」，再按 `SourceManager` → `PlaybackController` → `ControlPageApi` 分批搬
  - D2 决策：是否发布基于 master 的版本
  - **回归网的射程边界**：review 发现的 3 项（线程模型、计数语义、终态重入）在 11 个用例 + 28 项断言全绿的情况下都不会被抓到。
    下一轮若继续动播放链路，应把「失败 → 跳台 → 复位」抽成可测的纯状态机，而不是继续依赖设备侧人工复现
