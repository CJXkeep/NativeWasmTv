## 三、根因定位：多线路并存但无自动回退

以 CCTV-4 为例，把 6 条线路拆成独立频道逐条实测（probe 分组）：

| 线路 | 宿主侧探测 | 设备侧实测 |
| --- | --- | --- |
| 1 `raw.githubusercontent.com/ChiSheng9/iptv/master/TV20.m3u8` | HTTP 206，`#EXTM3U` | NOFRAME（内容实为 YouTube 播放列表，假源） |
| 2 `207.56.13.146:81/cdnlive/cctv4.m3u8` | HTTP 200，`#EXTM3U` | NOFRAME |
| 3 `38.75.136.137:98/...cctv4k.m3u8?auth=testpub` | HTTP 206 | **OK** 5105 ms / 6.62 MB |
| 4 `173.208.212.130:8181/1080p/cctv4.m3u8` | HTTP 206 | NOFRAME |
| 5 `74.91.26.218:82/live/cctv4hd.m3u8` | HTTP 206 | **OK** 8233 ms / 2.43 MB |
| 6 `107.150.60.122/live/cctv4hd.m3u8` | HTTP 206 | **OK** 4066 ms / 3.42 MB |

结论：

1. CCTV-4 的 6 条线路中有 3 条设备侧可用，但播放器停在**第 1 条**（假源）失败后**不回退**，用户看到的是"打不开"。
2. NOFRAME 的 5 个频道全部是多线路频道，问题不在"没有可用线路"，而在"没有按序尝试"。
3. 宿主侧探测通过 ≠ 设备侧可用（第 2、4 条即为例证），源筛选必须补设备侧口径。
4. 因此迭代的工作项 C（起播失败自动切换）应从 P1 提为 **A4 的前置**：没有 fallback 时，追加线路不产生任何收益。

## 四、对 A4 合并结论的修正

- 合并时**必须**保证每个频道的第 1 条是官方 CDN（现 100% 可用基线），聚合线路只追加在尾部；这样即使 fallback 尚未实现也不会劣化。
- 线路排序需要清洗掉：假源（内容为 YouTube 播放列表）、`?auth=test*` 临时授权参数、设备侧实测失败的条目。
