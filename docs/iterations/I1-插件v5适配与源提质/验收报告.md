## 三、发布信息

- 变更摘要：
  1. 插件协议 4 → 5：`HOST_PROTOCOL`、`cjs_sites_v5` 命名空间、按 ABI + `minSdk` 择优 native profile
  2. 内置源按**画质优先**追加 14 条聚合直连线路（≥720p 且验证到视频流），剔除 43 条黑名单/轮播/假源，新增 1 个频道
  3. `docs/cjs-plugin.md` 升到 protocol 5
  4. **起播失败自动回退改为默认开启** + 自动尝试上限 4 + 命中线路日志
     （原为默认关闭，等于整条回退链路不生效——这是 A 阶段实测「频道打不开」的直接原因）
  5. 控制页收敛：插件页改名「网站插件」并写清影响范围、站点目录 URL 折叠为高级项
- 发布流程（逐项执行，任一步不通过即停止）：
  1. `pwsh -File scripts/regression.ps1 -WithPlayback` 必须全绿（退出码 0）
  2. `pwsh -File scripts/check-sources.ps1` 确认内置源未劣化（当前基线：可用率 100%、无黑名单命中、无零可用频道）
  3. 打包 `assembleArm64Debug`（本机无 `armeabi-v7a`，arm32 flavor 保留但不发布）
  4. 签名不同：切换安装前先 `uninstall`，否则报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`
- 升级注意：自建 debug 与官方 release 签名不同，切换安装前先 `uninstall`；仅提供 arm64 产物
- 已知问题：
  - `webViewResolution` 默认 720P，75 寸下建议改 1080P/2K
  - 首次从 v4 升级 / `pm clear` 后首次播放需下载 CJS 站点插件（约 26 s 一次性成本）
  - 第三方聚合源"能验证到视频流"的比例仅 7%，故本轮不再追加未验证线路
  - 66 个频道中仅 24 个（36%）有多线路可回退，其余 42 个单线路频道无兜底——画质优先的代价，见回退报告第五节

## 四、回顾

- 做得好的：
  - 用应用自带的 `/api/playlist/merge` 做导入实测，比手写 SharedPreferences XML 更贴近真实路径，还能直接拿到分组与频道统计
  - 用 probe 分组把"频道级失败"拆成"线路级可用性"，一步定位到"缺自动回退"这一根因
  - 内置源"只追加不改序"，使本次改动在无 fallback 的情况下也不劣化
  - C 阶段没有直接动手改，而是先读代码确认「回退逻辑是否真的不存在」——结果是逻辑完整、
    只是被默认关闭的开关拦住，改动量从"写一套 fallback"缩到"改一个默认值 + 加上限"
  - B 阶段先验证前提（那 42 个"无兜底"频道到底稳不稳）再决定做不做补源——
    结果推翻了补源计划，避免了把稳定频道换成裸 IP 源的反向操作
  - D 阶段的回归用例把 A/B/C 的结论固化成断言（如「设备频道数必须等于 assets 解析值」），
    以后改内置源却忘了同步，回归会直接报出来
- 遇到的问题：
  - 首帧判定最初用 `logcat -t 200`，日志量大会把首帧行挤掉，造成 CCTV-1 假阴性；已改为 `-t 2000` 并用流量交叉验证
  - 聚合源频道名带标注后缀，直接导入无法合并线路；必须先归一化名称
  - 宿主侧探测通过不等于设备侧可用（CCTV-4 第 2、4 条即为例证）
  - **探测并发参数踩坑**：并发 32 + 超时 4s 会把 35 条里的 28 条误判为不可达（可用率 20%），
    而并发 8 + 超时 15s 是 100% 且更快——本场景下高并发"越慢越不准"。
    该配置还影响过历史结论（`probe-quality-fast.ps1` 用的正是它），已在脚本头部固化教训
  - 巡检报告初版把「本就无直连线路」的频道写成「直连全部失败」，属误导；
    已拆成「无直连（正常）/ 直连失败但有兜底 / 直连失败且无兜底（严重）」三类
- 下轮改进：
  - ~~优先做工作项 C（起播失败自动切换）~~ → 已完成（2026-09-25）：默认开启 + 尝试上限 4 + 命中线路日志
  - 源筛选补「设备侧口径」→ 已在 `check-sources.ps1` 的报告口径里显式标注
    「宿主判失败 ≠ 设备不可用」，并规定写入内置源前必须过 `device-sample-test.ps1`
  - 巡检的**趋势**比对需要累积多期数据才有意义（`-Baseline`），建议每 1~2 周跑一次
  - 单线路频道（42 个）无兜底，可用性取决于站点插件稳定性；若将来要提升覆盖率，
    应找**官方源**而非放宽聚合源门槛（本轮补源评估已给出结论）
  - 控制页 E 还剩「其余二级页是否存在技术项摆首屏」的复核
