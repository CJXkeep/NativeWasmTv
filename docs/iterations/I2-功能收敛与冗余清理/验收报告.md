## 五、回顾

- 做得好的：
  - 删除前先做完整触点调研，避免"删一半"：飞鼠的 `/api/pointer` 同时也是键盘/手柄通道，整块删才自洽
  - B3 抓住了关键区分：`onStreamDiscovered` 是 webview 频道的播放主路径（保留），只删"资源列表 + 手动播放"副产物
  - 每改一块立刻编译验证，把问题挡在小范围内
  - 用 `state.video` 替代 `recording.width/height`，删功能但保住画质可观测性
  - 拆分优先选"静态、无状态"的方法，成功率最高（41 个方法一次通过，仅需补 import）
- 遇到的问题：
  - 迭代计划里"清 `last_*_v2` 迁移键"是错的——它们是当前生效键，靠调研才纠正
  - GitHub 代理加速不能删（自动更新与 CJS 依赖），原计划"删或改回退"只能改为"保留"
  - 批量正则删除时误把 `` `r`n `` 字面写入 Java 文件；`resetPlaybackLayerImmediately` 有重载，搬移器搬错了版本
  - 模拟器实例 0 网络不可用（无默认路由、无 root），切回实例 1 才完成设备回归
- 下轮改进：
  - D 组剩余部分应先做"播放状态持有对象"重构，再搬 `ControlPageApi` / `SourceManager` / `PlaybackController`；否则 200+ 实例字段会让搬移错误率陡增
  - 清理失去调用者的 `WebSourceView` 三个远程输入方法
  - 补一层最小的自动化回归（频道加载 + 起帧 + 控制页接口），当前完全依赖手动真机
