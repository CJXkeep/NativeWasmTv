## 一、定位

**一台给家人用的电视——打开就能看，坏了会自己想办法，实在不行才让人按一次 OK。**

- 三件事按重要性排序：**把分散的公开源整理成一份能用的频道表** → **用尽量少的操作把它放出来** → **播不出来时自己兜底**。第三件是核心资产。
- 核心资产是**失败自愈**：播不出来时自动换线路、换封装、软解，而不是弹错误框让用户处理。
- 第一位用户是**不会折腾的家庭用户**；愿意自己准备订阅源的进阶用户走局域网网页配置。
- 单人维护的自用项目，不商业化、不做账号、不引入需要维护的服务端。
- **兼容基线**：Android 4.x（API 14）起，包含 Ku9 脚本体系与旧设备 TLS 栈。
  技术选型不得依赖更高版本 API；为兼容老设备存在的兜底能力，可以不给用户开关，但不要删掉。

## 二、设计原则

每条都对应一个可检验的后果，不是口号。

| # | 原则 | 检验方式 |
| --- | --- | --- |
| 1 | **默认零配置可用** | 装完即有台可播。任何"必须配置才能用"的设计直接判不合格 |
| 2 | **电视端只负责看** | 遥控器上只留：上下换台、OK 开面板、长按看线路、MENU 设置。复杂输入一律去手机网页 |
| 3 | **自动决策优于开关** | 软解、画质、换台方向、信息显示由程序判断；设置项只减不增（分类与上限见 §2.1） |
| 4 | **一切失败必须有终态** | 不允许"永远转圈 / 永远黑屏 / 静默无反馈"。新加异步链路前先回答"失败时用户看到什么" |
| 5 | **工程预算投在成功率，不投在功能数** | 新增一个源的价值，远低于"现有源多播成功 5%" |
| 6 | **先让时间可观测，再优化** | 起播、换台、换线各阶段先埋点出数字；没有数字不谈"变快了没有" |
| 7 | **做减法毫不留情** | 与"看"无关的东西，明确写进"不做"清单当承诺，而不是留着以后再说 |
| 8 | **验证纪律** | 模拟器只验连通性；手感、解码、长稳必须真机。未实测项一律标"未验证"，不得视为通过 |

### 2.1 开关的两类与上限

"设置项只减不增"需要一条可执行的判据，所以开关分两类，判定标准不同：

| 类别 | 判定标准 | 允许的形态 | 现有项（2026-09-25） |
| --- | --- | --- | --- |
| **兜底入口** | 存在"正确答案"（自动决策），但某些设备/网络下不适用 | 默认值就是"自动"；仅当自动回退仍不适用时由用户覆盖 | 解码方式、DNS、直播延迟、站点画质 |
| **用户偏好** | 不存在正确答案，因人/因屏而异 | 可直接暴露，但档位要少、语义要直白 | 开机自启、画面比例、界面大小、屏幕信息、自动切换备用线路 |

- **上限 12 项**（当前 11 项）。**新增一项必须删掉等量旧项**，并在提交说明里写清它属于哪一类。
- 兜底入口**不是"给用户的选项"**：默认路径不得依赖用户设置，老设备由程序自动回退；把兜底能力做成必选项等于违反原则 1。
- 现状偏差（已知，待收敛，不视为合规）：解码方式 / DNS / 直播延迟 / 站点画质 这四项目前与控制页其它设置并列，未收进"高级"折叠区。

## 三、北极星指标

所有改动都要能回答"命中哪一条"，答不上来就不做。

| 指标 | 目标 |
| --- | --- |
| 冷启动到起播 | ≤ 5 s（有缓存 ≤ 1 s） |
| 坏台自动离开耗时 | ≤ 20 s |
| 死台无限等待 | 0 |
| 实测画质 | 1080p 起步（75 寸电视） |
| 首次安装所需配置步骤 | 0 步 |
| 设置项数量 | ≤ 12（当前 11，只减不增） |
| 崩溃率 | 0 |

## 四、功能边界

### 核心——必须做好，不设开关

频道播放与切换（上下键 / 数字键 / 收藏）、分组与频道列表、EPG、内置源与在线订阅与本地导入、解码与画面比例、局域网控制页与二维码、自动更新、崩溃自愈、开机自启、时钟与网速叠加、**开机恢复上次频道与分组**。

### 可选——保留但收敛为最少开关

| 功能 | 理由 |
| --- | --- |
| 开机自启 | 家庭场景必需 |
| 自动切换备用线路 | 原则 4 的兜底，默认开 |
| 信息叠加（时间 / 网速 / 调试） | 三项合并为一个档位 |
| 画质优先 / 可用性优先 | 投影小屏与大屏需求相反 |
| 预加载下一频道 | 高风险实验功能，必须能关掉 |

### 不做——写进承诺

DIY 皮肤、多语言、账号体系、云同步、投屏与投屏协议、点播、统计上报、付费墙与 DRM 破解、需要维护的服务端。

**豁免：恢复上次播放位置不算"播放记录"。**
"播放记录"指可供用户浏览的历史列表、跨设备同步、外部内容收藏；
开机恢复到上次的频道与分组（`last_group_index_v2` / `last_channel_snapshot_v2`）属于"打开就能看"，归入核心，不在不做清单内。

### 内容与合规——三档

| 档 | 内容 | 允许？ |
| --- | --- | --- |
| 硬红线 | 破解 DRM、付费墙、订阅校验；抓取需登录的受保护内容 | **不做** |
| 灰色地带 | 调用平台公开但未文档化的 HTTP 接口取流（如央视频、Ku9 等站点适配） | **保留现状**：仅限个人自用，不公开分发、不上架、不商业化 |
| 正常 | 用户自带的订阅源、公开 IPTV 聚合源、用户自带 token/cookie 透传 | 支持 |

新增平台适配前，先按上表定档，并在本节登记。

## 五、执行纪律

1. 每次改动先回答：**命中哪条北极星指标**；答不上来就不做。
2. **不新增需要用户手动配置的开关**；新增一项必须删掉等量旧项，并声明它属于"兜底入口"还是"用户偏好"（§2.1）。
3. **不新增没有终态的异步链路**。
4. 删除功能时同步删代码、资源、控制页入口、设置键与文档，不留半截。
5. 文档与代码不得有事实冲突；未实测的一律标"未验证"。
   **决策与结论必须自包含**——不得把结论寄托在只有作者机器才存在的路径上；环境/调试类记录可以写本机绝对路径，但必须标明是"某台机器上的记录"。
6. 新增抽象前先问"现在有几个实现"——为单一实现引入接口属于过度设计。
